# Feature Specification: AI-Powered User Outreach Automation

**Feature Branch**: `001-ai-outreach`
**Created**: 2026-02-08
**Status**: Draft
**Input**: User description: "I am an online seller, I want to develop a function in the project which would scrape data (mainly user url address) from some site, and send some message to user, the message should be generated by ai (ai locate at remote server)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Web Scraping and Contact Collection (Priority: P1)

As an online seller, I want to scrape user contact information (primarily website URLs and email addresses) from target websites so that I can build a list of potential customers to reach out to.

**Why this priority**: This is the foundational capability - without collecting contact data, no outreach can occur. It provides immediate value by creating lead lists.

**Independent Test**: Can be tested by scraping a single website and verifying the collected URLs and emails are accurate and stored in the system. Delivers a functional lead database ready for message generation.

**Acceptance Scenarios**:

1. **Given** I have configured a target website URL, **When** I start the scraping task, **Then** the system must extract all available user URLs and email addresses from that website
2. **Given** the scraping task encounters an invalid URL, **When** processed, **Then** the system must log the error and continue processing other URLs
3. **Given** scraping is in progress, **When** I check the task status, **Then** I must see real-time progress updates including pages processed and contacts found
4. **Given** duplicate contacts are found, **When** the scraping completes, **Then** the system must store only unique contacts (deduplicated by email address)

---

### User Story 2 - AI Message Generation (Priority: P2)

As an online seller, I want to generate personalized outreach messages using AI so that I can send relevant and engaging communications to each potential customer without writing individual messages.

**Why this priority**: Message generation enables scalable personalized outreach. It depends on having contact data (US1) but can be tested independently with sample data.

**Independent Test**: Can be tested by providing sample scraped user data (URL/profile) and receiving AI-generated messages. Delivers a message generation system ready for sending.

**Acceptance Scenarios**:

1. **Given** I have collected user contact data with website URLs, **When** I request message generation, **Then** the system must send the user data to the remote AI server and receive a personalized message
2. **Given** the AI server is unavailable, **When** message generation is requested, **Then** the system must retry up to 3 times with exponential backoff before logging a failure
3. **Given** a user's website URL is provided, **When** the message is generated, **Then** the message must include personalized content based on information from that user's website
4. **Given** I have multiple contacts, **When** I generate messages in batch, **Then** each message must be unique and personalized for that specific contact

---

### User Story 3 - Message Sending and Tracking (Priority: P3)

As an online seller, I want to send the AI-generated messages to collected users and track delivery status so that I can monitor my outreach campaign's effectiveness.

**Why this priority**: This completes the outreach workflow by delivering messages. It depends on both scraping (US1) and message generation (US2) but sending can be tested with manually created messages.

**Independent Test**: Can be tested by taking pre-generated messages and verifying they are sent successfully with proper tracking. Delivers a functional message delivery and monitoring system.

**Acceptance Scenarios**:

1. **Given** I have generated messages for contacts, **When** I initiate the sending process, **Then** each message must be sent to the corresponding contact's email address
2. **Given** a message send fails, **When** the error occurs, **Then** the system must log the failure, mark the contact as 'failed', and continue processing other messages
3. **Given** messages are being sent, **When** I check the campaign status, **Then** I must see real-time counts of sent, failed, and pending messages
4. **Given** a message is successfully sent, **When** the send completes, **Then** the contact must be marked with status 'sent' and the timestamp recorded

---

### Edge Cases

- What happens when the target website blocks scraping attempts (rate limiting, CAPTCHA, IP bans)?
- What happens when a scraped URL contains no email addresses or contact information?
- How does the system handle malformed or invalid email addresses during scraping?
- What happens when the AI server returns inappropriate or irrelevant content?
- How does the system handle contacts who unsubscribe or request to be removed from future outreach?
- What happens when scraping encounters websites with different languages or character encodings?
- How does the system handle rate limiting on the email sending side to avoid being flagged as spam?
- What happens when the internet connection is lost during scraping or message sending?

## Requirements *(mandatory)*

### Functional Requirements

**Scraping Capabilities**:
- **FR-001**: System MUST allow users to input one or more target website URLs for scraping
- **FR-002**: System MUST extract email addresses from the provided website pages
- **FR-003**: System MUST extract website URLs and profile links from target pages
- **FR-004**: System MUST support concurrent scraping of multiple websites (configurable limit)
- **FR-005**: System MUST deduplicate collected contacts by email address
- **FR-006**: System MUST support aggressive scraping mode (20+ requests per second, robots.txt optional) with configurable settings to maximize scraping speed while managing blocking risks

**AI Message Generation**:
- **FR-007**: System MUST send collected user data (URL, profile info) to a remote AI server
- **FR-008**: System MUST receive and store AI-generated personalized messages for each contact
- **FR-009**: System MUST allow users to customize the message template/prompt sent to the AI
- **FR-010**: System MUST handle AI server errors with retry logic (3 attempts, exponential backoff)
- **FR-011**: System MUST validate that generated messages meet minimum length and quality criteria
- **FR-012**: System MUST allow users to review and edit AI-generated messages before sending

**Message Sending**:
- **FR-013**: System MUST send messages to collected email addresses using configured email service
- **FR-014**: System MUST support batch sending of messages with progress tracking
- **FR-015**: System MUST track delivery status for each sent message (sent, failed, pending)
- **FR-016**: System MUST implement rate limiting to avoid spam filters
- **FR-017**: System MUST provide a summary report after sending completes (total sent, failed, success rate)

**Data Management**:
- **FR-018**: System MUST persist scraped contacts in the local database
- **FR-019**: System MUST store AI-generated messages associated with each contact
- **FR-020**: System MUST maintain scraping history with timestamps and source URLs
- **FR-021**: System MUST allow users to view, filter, and export collected contacts
- **FR-022**: System MUST support deleting contacts and message history

**User Interface**:
- **FR-023**: System MUST provide a UI for configuring scraping tasks (URL input, concurrency settings)
- **FR-024**: System MUST display real-time progress for scraping, message generation, and sending operations
- **FR-025**: System MUST show a list of collected contacts with their status
- **FR-026**: System MUST allow users to trigger message generation and sending from the UI
- **FR-027**: System MUST provide error messages and logs for troubleshooting failed operations

### Key Entities

**Scraping Task**:
- Represents a scraping operation initiated by the user
- Attributes: target URLs, start time, end time, status (running, completed, failed), pages processed, contacts found
- Relationships: Has many Collected Contacts

**Contact**:
- Represents a potential customer scraped from a website
- Attributes: email address, website URL, name (if available), scraped date, source URL, status (pending, message_generated, sent, failed)
- Relationships: Belongs to Scraping Task, has one Generated Message

**Generated Message**:
- Represents an AI-generated outreach message for a specific contact
- Attributes: message content, generated timestamp, AI server response metadata, user edits flag, reviewed flag
- Relationships: Belongs to Contact

**Outreach Campaign**:
- Represents a batch message sending operation
- Attributes: campaign name, start time, end time, status (preparing, sending, completed), total contacts, sent count, failed count
- Relationships: Has many Contacts

**Scraping Log**:
- Represents individual scraping events for debugging
- Attributes: timestamp, URL scraped, status (success, error, blocked), error message, pages processed, emails found

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can scrape 100 websites and collect 500+ unique email contacts in under 30 minutes
- **SC-002**: AI message generation completes for 100 contacts in under 5 minutes with 95% success rate
- **SC-003**: Message sending achieves 90% delivery success rate (excluding invalid emails and bouncebacks)
- **SC-004**: 80% of AI-generated messages are approved by users without requiring edits (based on "reviewed without edits" flag)
- **SC-005**: Users can complete the full workflow (scrape → generate messages → send) for 50 contacts in under 1 hour
- **SC-006**: System handles scraping failures gracefully - 95% of scraping tasks complete successfully even when some individual pages fail
- **SC-007**: UI provides real-time progress updates with latency under 2 seconds for all long-running operations

## Assumptions

1. **Remote AI Server**: A remote AI service is already available and accessible via API. The system will call this service with user data and receive generated messages.

2. **Email Service**: The existing email sending infrastructure in the project (from `EmailMarketingTaskEntity` and related modules) will be reused for sending outreach messages.

3. **Scraping Politeness**: Default scraping will use aggressive mode (20+ requests per second, robots.txt optional) for maximum speed. Users can configure request rates and robots.txt respect in the UI settings.

4. **Contact Storage**: Contacts and messages will be stored in the existing SQLite database using TypeORM, following the project's current database architecture.

5. **Browser Automation**: Scraping will use the existing Puppeteer infrastructure (`src/taskCode.ts`, `src/childprocess/`) to handle dynamic websites and JavaScript-rendered content.

6. **Message Content**: AI-generated messages will be text-based email messages. The system will not handle attachments or HTML formatting initially unless specified later.

7. **User Permissions**: The user has legal authority to scrape the target websites and send outreach messages. The system will include basic compliance features (opt-out handling) but legal compliance is the user's responsibility.

8. **Language Support**: The system will support scraping websites in multiple languages, but AI-generated messages will default to English unless the user specifies otherwise in the message template.
